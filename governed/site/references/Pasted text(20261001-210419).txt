# CANVAS-PARITY FEATURE & FUNCTIONALITY PROMPT
## Scholaris Global Learning LMS (first tenant: OakHaven Global University)

---

## 0. ROLE & GOAL

You are the **LMS Feature-Parity Architect** for Scholaris Global Learning. Build an LMS whose **features, workflows and user experience match what instructors, students, designers and admins expect from Canvas LMS**. Build it in Scholaris's own architecture (multi-tenant, database-per-tenant, SIS as source of truth, outbox events, governed AI).

**Clean-room rule:** Match functionality, not implementation. Do **not** copy Canvas source code, UI assets, icons, or the names "Canvas"/"Instructure". Use Scholaris names for every feature. Write all UI copy originally.

For every feature below, deliver the following. A feature missing any of these is **not done**:
- UI screens (web responsive plus mobile PWA)
- REST + GraphQL API and domain events
- Server-side permissions
- Seed data for the OakHaven demo tenant
- Tests, including the accessibility test (WCAG 2.2 AA)

## 1. ROLES & PERMISSIONS MODEL

**Course roles:** Teacher, TA, Designer, Student, Observer.
**Account roles:** Account Admin, Sub-Account Admin, plus custom roles.

- Build a **permissions matrix UI** with granular toggles per role, for example:
  - Manage course content, Grade submissions, View all grades, Manage sections, Send messages
  - View/restore deleted content, Manage LTI, Change course state, Masquerade
- Permissions **inherit down the account → sub-account tree**. A parent admin can **lock** a permission so sub-accounts cannot change it.
- **Observers** are linked to specific students. They see only the linked student's grades, calendar and submissions, subject to consent.
- **Act As / masquerade:** admin-only and time-boxed, shown with a persistent banner, fully audited.
- **Student View:** teachers preview the course as a fake test student. The test student's data is isolated and resettable.

## 3. COURSE NAVIGATION (per-course left menu)

Teachers can **reorder, hide or show** every course tab in Settings → Navigation. Hidden tabs remain reachable for teachers but are invisible to students. Tabs with no content auto-hide from students.

### 3.1 Home
- Choose the home page type:
  - Recent Activity stream
  - A designated Front Page (wiki page)
  - Modules
  - Assignments list
  - Syllabus
- Sidebar: Publish/Unpublish course, Import existing content, Import from Commons-equivalent, Choose home page, View course stream, New announcement, New analytics, View course notifications, To Do, Coming Up.
- Course setup checklist for new courses.

### 3.2 Announcements
- Rich-content announcements with attachments.
- Options: delay posting (scheduled), allow replies/likes, section-specific targeting, podcast feed.
- Read/unread tracking, lock replies, and show the latest announcement(s) on the home page.

### 3.3 Syllabus
- Editable rich-content description on top.
- **Auto-generated course summary** below it, listing every dated assignment, quiz, discussion and event in date order. It updates automatically when dates change.

### 3.4 Modules (the backbone)
- Modules contain ordered items: Pages, Assignments, Quizzes, Discussions, Files, Text headers, External URLs, External tools (LTI).
- Items are drag-and-drop reorderable and can be moved between modules. Indentation levels are supported.
- **Publish/unpublish** works per module and per item. Unpublished items are invisible to students.
- **Prerequisites:** a module can be locked until prior modules are complete.
- **Lock until** a date.
- **Requirements**, per item: view, mark as done, contribute, submit, or score at least X. The module can require all requirements or any one of them.
- **Sequential progression:** students must complete items in order. This is **enforced server-side**.
- The student sees progress icons per item and **Next/Previous navigation buttons** at the bottom of every module item.
- **Mastery Paths (conditional release):** score ranges on an assessment unlock different follow-up items per student.
- Duplicate a module, collapse/expand all, view progress for all students (teacher).
- **Assign-to per module** (differentiation), covering specific sections, groups or students.

### 3.5 Assignments
- Grouped by **Assignment Groups** with optional weighting and drop rules (drop lowest/highest N, never drop X).
- **Assignment editor fields:**
  - Title and rich description
  - Points
  - Assignment group
  - Display grade as: points, percentage, complete/incomplete, letter grade, GPA scale, or not graded
  - Exclude from final grade
  - Submission types: online text entry, file upload (with allowed extensions), website URL, media recording, student annotation, external tool, on paper, or no submission
  - Number of attempts
  - Group assignment (with group set, grade individually or as a group)
  - Peer reviews: manual or automatic, count per student, anonymous option, due date
  - Moderated grading: multiple graders, final grader selects
  - Anonymous grading
  - Plagiarism review hook (LTI)
  - **Assign to**: everyone, sections, groups, or individual students, each with its own due / available-from / until dates
- **Student annotation submissions:** the student annotates a teacher-provided document inline.
- **Late/missing policies** at course level:
  - Automatically apply a grade for missing submissions
  - Deduct X% per day/hour late, with a lowest possible grade
- **Submission detail page:** status, attempt history, feedback comments (text, media, file attachments), and the rubric view.
- Bulk edit dates across all assignments. Rubric attachment. Outcome alignment.
- **Student-facing badges:** Missing, Late, Excused, Resubmitted.

### 3.6 Discussions
- **Types:** focused (single level) or threaded replies.
- **Options:**
  - Graded (becomes an assignment)
  - Users must post before seeing replies
  - Enable podcast feed
  - Allow liking, including "only graders can like"
  - Sort by likes
  - Group discussion (creates one per group)
  - Delayed availability
  - Section-specific
  - Anonymous or partially anonymous
  - Checkpoints: reply to topic plus N required replies, with separate due dates
- Pin, close for comments, subscribe/unsubscribe, unread counts, mark all read, edit history, report reply, mentions (@user notifications).
- Deleted replies leave a tombstone so threads stay intact.

### 3.7 Grades (Gradebook)
**Teacher Gradebook (spreadsheet UI)**
- Students in rows, assignments in columns. Assignment-group totals and the final total. Sticky columns.
- Keyboard navigation and inline cell editing. Cell **status colors**: late, missing, resubmitted, dropped, excused.
- Filters: section, module, assignment group, student group, grading period.
- Sorting by column. Column arranging (by due date, points, module).
- Hide/show unpublished items.
- Row views: secondary info (section, SIS ID, login ID); show/hide notes column.
- **Grade detail tray:** status overrides, comments, submission link, late-policy adjustment.
- **Curve grades.** **Set default grade.** **Message students who** (have not submitted / not graded / scored less than or more than X).
- **Grading periods** (term-based) with close dates that lock edits.
- **Grading schemes:** letter grade, pass/fail and GPA schemes, editable at account or course level.
- **Final grade override** column.
- **Grade posting policies:**
  - Automatic posting, or manual posting per assignment
  - Post grades / Hide grades actions, targeted to everyone or to graded students only, by section
  - Students see a "hidden" eye icon until grades are posted
- **Gradebook history:** full audit log of every change, with grader, before/after values and timestamp, filterable.
- **Import/export CSV** with preview and a confirmation of changes.
- **Individual Gradebook view:** one student and one assignment at a time, screen-reader optimized.
- **Learning Mastery Gradebook:** outcomes-based view showing mastery per outcome per student.

**Student Grades page**
- Every item shown with score, status, rubric, and comments.
- **What-If scores:** the student enters hypothetical scores and sees the recalculated total. The calculation is client-side only and never saved.
- Totals are calculated per the weighting rules. Hidden/unposted grades are excluded.
- The teacher can hide totals from students per course.

### 3.8 SpeedGrader-equivalent (sequential grader)
- Student selector: previous/next, sort, filter to "needs grading", **hide student names**.
- **Document preview** with inline annotations:
  - Point, highlight, strikeout, freehand drawing, text box, and area comments
  - Annotations stored separately from the immutable submission
- Views for submission attempts, and for rubric grading with interactive rating selection and auto-summed points.
- Comment box with text, media recording, file attachments, and a comment library of saved comments.
- Group grading mode, moderated grading, and anonymous grading.
- Status menu per student: late (with override days), missing, excused, none.
- **Resubmission indicator.** Pairs with posting policy (grades hidden until posted).
- Grade saves use optimistic concurrency. A stale edit returns 412, and the UI shows "grade changed by X, reload".

### 3.9 People
- Roster with name, login ID, SIS ID, section, role, last activity, and total activity time.
- Filter by role or section. Search.
- **+ People** adds users by email, login ID or SIS ID, only when permitted. Enrollments come from the SIS projection and are not invented.
- Per-user actions: edit sections, edit role, link to observer, remove, deactivate (inactive enrollments keep their grades), user details, **access report** (pages viewed, times, participations).
- **Groups sub-tab:**
  - Create group sets
  - Allow self sign-up, with group size limits
  - Auto-assign randomly, balancing by section
  - Assign group leaders
  - Drag-and-drop students between groups
  - Import group CSV
  - Clone group set

### 3.10 Pages
- Wiki pages with the rich content editor. Revision history with restore. Front page designation.
- Editing permissions: teachers only, teachers + students, or anyone. Page to-do date. Assign-to.
- Links to other course content, auto-updated when that content is renamed.

### 3.11 Files
- Folder tree, drag-and-drop upload, and bulk actions (move, delete, download zip).
- Publish, unpublish, schedule availability, or hidden-but-linkable, per file or folder.
- Usage rights / license designation, with its required enforcement.
- Preview for docs, PDFs, images and media. Quotas at course, user and group level. Restore deleted files.
- Files are scanned before promotion.

### 3.12 Quizzes (implement the modern quiz engine)
**Question types**
- Multiple choice, multiple answer, true/false
- Fill-in-the-blank, multiple fill-in-blanks
- Matching, ordering, categorization, hot spot
- Numeric (exact, range, margin, precision), formula (variable-based)
- Essay, file upload, stimulus (shared passage), text (no question)

**Item banks**
- Shared across courses, with tags and version history.
- Random question pools ("pick N from bank/tag").

**Quiz settings**
- Time limit; multiple attempts with keep highest/latest/average; cooling period between attempts.
- Shuffle questions and answers; one question at a time with a lock-after-answer option.
- Access code, IP filtering, availability window.
- Result visibility controls: show responses, show correct answers, show them only after a date.
- Calculator (basic / scientific).

**Accommodations and moderation**
- Per-student accommodations: extra time (percentage or minutes), extra attempts.
- **Moderate** page: extend time for an in-progress attempt, grant an additional attempt, reopen.

**Attempts and grading**
- Autosave with version checks. Idempotent submit.
- Auto-grading for objective items. Essays route to a manual grading queue in the sequential grader.
- Regrade options when a question is edited after attempts.

**Reports**
- Student analysis, item analysis (difficulty, discrimination), outcomes analysis.

**Other quiz modes**
- Practice quizzes (ungraded) and graded surveys / ungraded surveys (optionally anonymous).
- Proctoring only through an optional LTI integration.

### 3.13 Outcomes
- Account-level and course-level outcomes, organized in folders.
- Mastery scale and proficiency ratings, with a calculation method: decaying average, n-mastery, latest, highest, average.
- Import standards sets. Align outcomes to rubrics and quiz items.
- Student mastery view. Outcome results reports.

### 3.14 Rubrics
- Rubric builder: criteria rows, rating columns with points, point ranges, and long descriptions. Free-form comments option.
- "Use for grading" toggle. Hide score total. Outcome-linked criteria.
- Rubric library, with rubrics reusable across courses.
- Rubric versions lock once used for grading. Editing creates a new version.

### 3.15 Collaborations
- Create shared documents (via connected cloud-doc providers through LTI/OAuth) with selected users or groups.

### 3.16 Conferences / Live
- Scheduled live sessions via Zoom and the in-house connectors.
- Join links shown on course and calendar. Recordings listed with retention rules.
- Attendance is imported as external assertions.

### 3.17 Course Analytics
- **Course-level analytics:**
  - Weekly online activity (page views, participations)
  - Average grade per assignment vs section
  - On-time / late / missing breakdown per assignment
- **Student-level analytics:** activity, submissions and grades over time.
- Message students directly from charts. Export CSV.
- Analytics are derived metrics and never a grade source.

### 3.18 Course Pacing (optional feature)
- Pace plans that auto-assign due dates per student from their start date and course duration.
- Blackout dates, section-specific paces, and student-specific paces.

### 3.19 Settings (per course)
- **Course Details tab:**
  - Name, code, image, time zone, term, participation dates
  - Language, grading scheme, license, visibility (course/institution/public)
  - Format (online/on-campus/blended)
  - Toggles: students can create discussions, edit or delete posts, attach files, create groups; hide totals; hide grade distribution graphs
- **Sections tab:** create and edit sections, section-level start and end dates, cross-listing (from SIS).
- **Navigation tab:** drag to reorder or hide course tabs.
- **Apps tab:** add, configure or remove LTI tools; placements.
- **Feature Options tab:** course-level toggles for optional features.
- **Integrations** tab.
- **Sidebar actions:** Student View, Copy this course, Import course content, Export course content, Reset course content, Conclude course, Delete course, Course statistics, Course calendar, Conclude/unconclude.

## 14. ACCEPTANCE TESTS (must pass for Canvas-parity sign-off)

1. **Course build:** a teacher builds a course with 3 modules, prerequisites and sequential progression. Student View confirms locking; Next/Previous buttons work.
2. **Differentiated assignment:** the assignment is assigned to Section A with a due date Friday, and to one student with an extension to Monday. Each sees only their own dates; the Gradebook reflects both.
3. **Late policy:** a submission arriving 2 days late is deducted automatically. The Gradebook shows the late color. A teacher override is logged in Gradebook history.
4. **Grading and posting:** the sequential grader supports inline annotation and rubric scoring. The grade stays hidden under a manual posting policy until "Post grades" is used. The student sees the grade only after posting.
5. **Quiz accommodation:** a quiz item bank pulls 5 random questions. A student with a 50% extra-time accommodation gets the adjusted timer. An essay question routes to manual grading.
6. **Mastery Paths:** a score of 90%+ unlocks enrichment, 70–89 unlocks practice, and below 70 unlocks remediation.
7. **Discussion checkpoints:** a graded discussion with checkpoints (1 post + 2 replies) is graded against both checkpoints.
8. **What-If:** What-If scores recalculate the student's total without saving. Weighted groups and drop-lowest are applied correctly.
9. **Blueprint sync:** the blueprint pushes locked due dates to 3 associated courses, and local edits to locked items are blocked.
10. **Course copy:** course copy with date shifting moves every due date to the new term.
11. **Observer alerts:** the observer receives an alert when the linked student has a missing assignment.
12. **Inbox scoping:** a message to "All students in Section B" reaches only active Section B students. A cross-tenant recipient is impossible.
13. **Admin permissions:** an admin locks a permission at the root account, and a sub-account cannot unlock it.
14. **LTI grade passback:** an LTI 1.3 tool launched from a module item returns a score via AGS, and it appears in the Gradebook as unposted.
15. **Accessibility gate:** automated and manual accessibility checks pass on Dashboard, Modules, Gradebook, sequential grader and Quiz-taking.

2. Module-by-Module Functional Specifications
2.1 Course Engine & Content Management
Block-Based WYSIWYG Editor
	Content Model: Content is saved as a validated JSON AST (Abstract Syntax Tree) alongside a server-rendered, sanitized HTML snapshot.
	Feature Support: Semantic headings, accessible tables, responsive image/video embeds, LaTeX math equations (rendered via MathJax/KaTeX), callout boxes, syntax-highlighted code snippets, and LTI Deep Link embeds.
	Accessibility Scanner: Inline client-side and server-side scanner validating image alt tags, heading hierarchy continuity, color contrast ratios, table header scope attributes, and link text context.
Prerequisite Locking & Sequential Pathways
	Locking Rules: Modules can require prior module completion, specific unlock dates, or minimum score thresholds on prerequisite assignments.
	Path Enforcement: Server-side access gates reject direct URL access to module_items if prior requirements evaluate to false for the requesting user_id.
Blueprint Master Courses
	Three-Way Diff Engine: When pushing updates from a Blueprint Master, the system compares:
	The initial Blueprint state.
	The modified Blueprint state.
	The subscriber course state.
	Attribute Locking: Administrators can lock specific attributes (e.g., Title, Due Dates, Content Body, Points Possible). Local instructor edits to unlocked attributes are preserved during sync.
	Sync Execution: Blueprint pushes run as asynchronous background jobs using idempotent migration scripts, emitting detailed impact reports (added, modified, skipped items).
Common Cartridge & QTI Import Engine
	Sanitization Workspace: Imports execute in an isolated sandbox. External file links are scanned for malware, HTML content is sanitized against script injection, and unsupported proprietary structures map to fallback ContentPages.
	Supported Formats: Common Cartridge v1.0–v1.3, QTI v1.2, and QTI v2.1.
	Migration Report: Generates a deterministic report summarizing converted items, missing media assets, and unmapped assessment question types.
2.2 Assessment, Quizzes & SpeedGrader
Submission Pipeline
	Modes: File Upload (enforcing file extension allowlists), Online Text Entry, Website URL, Media Recording (audio/video capture), On-Paper Marker, and LTI External Tool Deep Link.
	Quarantine Lifecycle: File uploads stream directly to a quarantine prefix in object storage. A background worker executes MIME verification, virus scanning, and policy classification before moving the asset to the tenant's canonical namespace.
Quiz Engine & Snapshotting
	Snapshot on Publish: Publishing a quiz creates an immutable QuizSnapshot. Subsequent edits to the source question bank do not alter active student attempts.
	Attempt Execution:
	Authorization: Validates enrollment status, open availability window, remaining attempt allowance, and accommodation overrides.
	Randomization: Generates a cryptographically secure seed (BIGINT) to select questions from pools and shuffle answer options reproducibly.
	Autosave & Submit: Client emits a periodic heartbeat autosaving progress with optimistic version locking. Final submit executes as an idempotent database transaction.
	Grading Queue: Objective items (multiple choice, matching, true/false) auto-grade immediately. Subjective items (essays, short answer) enter the SpeedGrader human evaluation queue.
SpeedGrader & Annotation Architecture
	Split-Pane Interface: Renders student submission documents on the left and grading/rubric tools on the right.
	Annotation Layer: Document rendering converts submissions to PDF/HTML assets. Annotations (highlights, strike-throughs, freehand drawing, point comments) are stored as a separate, immutable SVG/JSON layer tied to the grader’s identity and timestamp.
	Moderated & Anonymous Grading: Hides student identity metadata when anonymous grading is enabled. Moderated assignments allow multiple graders to draft evaluations, which a final moderator reconciles into a single posted score.

Gradebook & Posting Policies
	Calculation Engine: Supports points-based and weighted assignment group systems. Automatically applies drop-lowest rules, late submission percentage deductions per day/hour, and missing submission default scores.
	What-If Scoring: Enables students to input hypothetical scores on upcoming or unsubmitted assignments to dynamically preview final course grade impacts without mutating database records.
	Posting Policies:
	Automatic Release: Scores publish to students immediately upon entry.
	Manual Release: Scores remain hidden behind a grades_released = FALSE flag until the instructor explicitly triggers a bulk grade release for the section or course.
2.3 Communication & Collaboration
Threaded Discussions
	Materialized Path Indexing: Discussion replies store a materialized path string (e.g., 0001.0004.0002) and depth integer, enabling single-query hierarchical retrieval and cursor pagination.
	Tombstone Deletion: Deleting a reply in a active thread converts the reply text to a tombstone notice while preserving child context and downstream thread continuity.
Section-Scoped Inbox & Announcements
	Recipients Validation: Messaging endpoints resolve recipient validity on the server using active section membership tables. Arbitrary cross-course or cross-tenant addressing is strictly blocked.
	Announcements: Supports delayed publication dates and section-specific targeting. Publishes through the outbox pipeline to generate branded email, SMS, and push notification payloads based on user-configured preferences.

Key Operational Controls
	Resolution Independence: All coordinates inside the geometry payload are relative ratios. Frontends render SVG elements dynamically over page viewport layers:
〖"Pixel" 〗_X=〖"Geometry" 〗_X×"Viewport Width" 
〖"Pixel" 〗_Y=〖"Geometry" 〗_Y×"Viewport Height" 
	PDF Flattening & Export Pipeline: When exporting a graded document to PDF, a server-side headless chrome renderer or PDF engine (like PDFium) rasterizes the SVG layer directly into the underlying document stream, embedding annotations into standard PDF annotation objects (/Annots).
	Moderated Grading Isolation: Separate submission_annotation_documents records exist for each assigned grader. When "Anonymous/Moderated Grading" is active, graders cannot see each other's annotation layers until the final moderator publishes the composite evaluation.
This WebSocket message protocol governs real-time, low-latency collaborative annotation editing within SpeedGrader. It handles multi-grader state synchronization, operational transformation/deltas, live cursor/selection presence, and optimistic locking reconciliation for instructors and TAs evaluating the same submission attempt.
Protocol Overview & Connection Lifecycle
	Transport: Secure WebSockets (wss://) with fallback to HTTP/2 Server-Sent Events (SSE) + REST.
	Serialization: JSON over WebSocket (text frame) for standard client payloads; optional Protocol Buffers over WebSocket (binary frame) for dense freehand path streams.
	Authentication: Handled during handshake via session token or JWT in subprotocol header (Sec-WebSocket-Protocol: speedgrader-v1, token.<jwt_token>).

Heartbeat & Connection Recovery
	Ping/Pong Cycle: Client sends {"type": "PING"} every 15 seconds. Server responds with {"type": "PONG"}. If no frame arrives within 45 seconds, connection terminates.
	Reconnection Protocol: On reconnection, the client includes last_sequence_number in the SESSION_INIT request:
"Missed Events Range"=["last_sequence_number" +1…"current_server_sequence" ]
The server replays missed ANNOTATION_DELTA frames from Redis cache or returns a SESSION_INIT snapshot if the disconnect gap exceeds buffer retention.

2. Coordinate System Normalization Matrix
SpeedGrader UI geometries are saved as relative ratios (0.0000→1.0000) to guarantee screen-resolution independence. PDFium uses standard PDF points (1/72" inch" ) with an origin (0,0) located at the bottom-left of the page media box.
Transformation Equations
For a given page with PDF dimensions 〖"PageWidth" 〗_"pt"  and 〖"PageHeight" 〗_"pt" :
〖"PDF" 〗_X=〖"Ratio" 〗_X×〖"PageWidth" 〗_"pt" 
〖"PDF" 〗_Y=(1.0-〖"Ratio" 〗_Y )×〖"PageHeight" 〗_"pt" 
〖"PDF" 〗_"Width" =〖"Ratio" 〗_"Width" ×〖"PageWidth" 〗_"pt" 
〖"PDF" 〗_"Height" =〖"Ratio" 〗_"Height" ×〖"PageHeight" 〗_"pt" 
Note: Because PDF Y-coordinates increase moving upward, top-down web coordinates (〖"Ratio" 〗_Y) must be flipped relative to 〖"PageHeight" 〗_"pt" .
3. Go + PDFium Flattening Implementation
This Go implementation uses the native [github.com/klippa-app/go-pdfium](https://github.com/klippa-app/go-pdfium) CGO bindings to parse geometry primitives, construct native PDF annotation objects, and execute atomic page flattening (FPDFPage_Flatten).

package pdfiumexporter

import (
	"encoding/json"
	"fmt"

	"github.com/klippa-app/go-pdfium"
	"github.com/klippa-app/go-pdfium/requests"

type AnnotationItem struct {

	PageNumber     int             `json:"page_number"` // 1-indexed
	AnnotationType string          `json:"annotation_type"`
	Geometry       json.RawMessage `json:"geometry"`

	Content        string          `json:"content,omitempty"`
}

type AnnotationStyle struct {
	Color   string  `json:"color"` // Hex format e.g. "#E53E3E"
	Opacity float64 `json:"opacity"`
}

type PointGeometry struct {
	X float64 `json:"x"`
	Y float64 `json:"y"`
}

type HighlightGeometry struct {
	Rects []Rect `json:"rects"`
}

type Rect struct {
	X      float64 `json:"x"`
	Y      float64 `json:"y"`
	Width  float64 `json:"width"`
	Height float64 `json:"height"`
}

// FlattenDocument executes PDFium page mutation and bakes annotations into the static content stream.
func FlattenDocument(
	instance pdfium.Pdfium,
	pdfBytes []byte,
	annotations []AnnotationItem,
) ([]byte, error) {
	// 1. Load PDF Document from Memory
	doc, err := instance.FPDF_LoadMemDocument(&requests.FPDF_LoadMemDocument{
		Data: pdfBytes,
	})
	if err != nil {
		return nil, fmt.Errorf("failed to load PDF in PDFium: %w", err)
	}
	defer instance.FPDF_CloseDocument(&requests.FPDF_CloseDocument{
		Document: doc.Document,
	})

	// 2. Group Annotations by Page Number
	pageMap := make(map[int][]AnnotationItem)
	for _, item := range annotations {
		pageMap[item.PageNumber] = append(pageMap[item.PageNumber], item)
	}

	// 3. Process Each Page
	pageCountResp, err := instance.FPDF_GetPageCount(&requests.FPDF_GetPageCount{
		Document: doc.Document,
	})
	if err != nil {
		return nil, err
	}

	for pageIdx := 0; pageIdx < pageCountResp.PageCount; pageIdx++ {
		pageNumber := pageIdx + 1
		items, exists := pageMap[pageNumber]
		if !exists || len(items) == 0 {
			continue
		}

		// Open Page
		page, err := instance.FPDF_LoadPage(&requests.FPDF_LoadPage{
			Document: doc.Document,
			Index:    pageIdx,
		})
		if err != nil {
			return nil, fmt.Errorf("failed to load page %d: %w", pageNumber, err)
		}

		// Get Page Dimensions in Points
		widthResp, _ := instance.FPDF_GetPageWidthF(&requests.FPDF_GetPageWidthF{Page: page.Page})
		heightResp, _ := instance.FPDF_GetPageHeightF(&requests.FPDF_GetPageHeightF{Page: page.Page})
		pageWidth := widthResp.Width
		pageHeight := heightResp.Height

		// 4. Inject Native PDF Annotations
		for _, item := range items {
			switch item.AnnotationType {
			case "HIGHLIGHT":
				var geom HighlightGeometry
				if err := json.Unmarshal(item.Geometry, &geom); err == nil {
					for _, r := range geom.Rects {
						// Coordinate Conversion
						pdfX := r.X * pageWidth
						pdfY := (1.0 - r.Y - r.Height) * pageHeight
						pdfW := r.Width * pageWidth
						pdfH := r.Height * pageHeight

						// Add Native Highlight Annotation to PDF Page
						_, _ = instance.FPDFPage_CreateAnnot(&requests.FPDFPage_CreateAnnot{
							Page:     page.Page,
							Subtype:  pdfium.FPDF_ANNOT_HIGHLIGHT,
							Rect:     &pdfium.FPDF_FS_RECTF{Left: float32(pdfX), Top: float32(pdfY + pdfH), Right: float32(pdfX + pdfW), Bottom: float32(pdfY)},
						})
					}
				}

			case "POINT_COMMENT":
				var geom PointGeometry
				if err := json.Unmarshal(item.Geometry, &geom); err == nil {
					pdfX := geom.X * pageWidth
					pdfY := (1.0 - geom.Y) * pageHeight

					// Create Text Pin Annotation
					annot, _ := instance.FPDFPage_CreateAnnot(&requests.FPDFPage_CreateAnnot{
						Page:    page.Page,
						Subtype: pdfium.FPDF_ANNOT_TEXT,
						Rect:    &pdfium.FPDF_FS_RECTF{Left: float32(pdfX), Top: float32(pdfY + 16), Right: float32(pdfX + 16), Bottom: float32(pdfY)},
					})

					// Set Text Contents
					_ = instance.FPDFAnnot_SetStringValue(&requests.FPDFAnnot_SetStringValue{
						Annotation: annot.Annotation,
						Key:        "Contents",
						Value:      item.Content,
					})
				}
			}
		}

		// 5. Flatten All Page Annotations into Page Content Stream
		_, err = instance.FPDFPage_Flatten(&requests.FPDFPage_Flatten{
			Page: page.Page,
			Flag: pdfium.FPDF_FLATTEN_PRINT, // Bake for print/viewing compatibility
		})
		if err != nil {
			return nil, fmt.Errorf("failed to flatten annotations on page %d: %w", pageNumber, err)
		}

		// Close Page Handle
		_ = instance.FPDF_ClosePage(&requests.FPDF_ClosePage{Page: page.Page})
	}

	// 6. Save Document Bytes
	saveResp, err := instance.FPDF_SaveAsCopy(&requests.FPDF_SaveAsCopy{
		Document: doc.Document,
		Flags:    pdfium.FPDF_SAVE_NO_INCREMENTAL,
	})
	if err != nil {
		return nil, fmt.Errorf("failed to serialize flattened PDF: %w", err)
	}

	return saveResp.FileBytes, nil
}
4. Key Performance Controls
Optimization Layer	Implementation Rule
CGO Worker Pool	Reuses a bounded pool of pre-initialized PDFium worker processes/goroutines to eliminate FPDF_InitLibrary per-request overhead.
Stream-Based I/O	Leverages FPDF_SaveAsCopy directly into memory buffers or pre-signed storage streams to eliminate intermediate local disk reads/writes.
Font Substitution	Maps point comment callout fonts to standard PDF Base-14 fonts (Helvetica, Times-Roman) to prevent font embedding bloat during flattening.
Because PDFium relies on underlying C bindings (CGO), creating and destroying library instances per request creates severe lock contention and memory fragmentation. This implementation uses a thread-safe worker pool pattern that manages a fixed set of initialized PDFium instances with worker channels, context cancellation, and grace shutdown controls.
Go
package pdfiumexporter

import (
	"context"
	"errors"
	"fmt"
	"log"
	"sync"
	"time"

	"github.com/klippa-app/go-pdfium"
	"github.com/klippa-app/go-pdfium/single_threaded"
)

var (
	ErrPoolClosed   = errors.New("worker pool is closed")
	ErrJobCancelled = errors.New("job context cancelled prior to execution")
)

// ExportJob represents a single SpeedGrader PDF flattening task.
type ExportJob struct {
	JobID       string
	SubmissionID string
	PDFBytes    []byte
	Annotations []AnnotationItem
	
	// Result handling
	ResultChan  chan ExportResult
	Ctx         context.Context
}

// ExportResult contains the processed PDF byte payload or execution errors.
type ExportResult struct {
	JobID          string
	FlattenedBytes []byte
	Duration       time.Duration
	Err            error
}

// PDFWorkerPool manages a fixed set of PDFium single-threaded worker instances.
type PDFWorkerPool struct {
	poolSize   int
	jobsChan   chan ExportJob
	workerWg   sync.WaitGroup
	closeOnce  sync.Once
	isClosed   bool
	closedLock sync.RWMutex

	// PDFium engine pool reference
	pdfiumPool pdfium.Pool
}

// NewPDFWorkerPool initializes a high-concurrency PDFium worker pool.
func NewPDFWorkerPool(poolSize int, bufferSize int) (*PDFWorkerPool, error) {
	if poolSize <= 0 {
		poolSize = 4 // Default to sensible core count fallback
	}

	// Initialize single-threaded PDFium instance pool
	// go-pdfium single_threaded mode prevents C-level thread affinity crashes
	p := single_threaded.Init(single_threaded.Config{})

	pool := &PDFWorkerPool{
		poolSize:   poolSize,
		jobsChan:   make(chan ExportJob, bufferSize),
		pdfiumPool: p,
	}

	// Start worker goroutines
	pool.workerWg.Add(poolSize)
	for i := 1; i <= poolSize; i++ {
		go pool.worker(i)
	}

	log.Printf("[PDFWorkerPool] Initialized pool with %d workers and buffer depth %d", poolSize, bufferSize)
	return pool, nil
}

// Submit enqueues an export job into the channel. Returns error if pool is closed.
func (p *PDFWorkerPool) Submit(job ExportJob) error {
	p.closedLock.RLock()
	defer p.closedLock.RUnlock()

	if p.isClosed {
		return ErrPoolClosed
	}

	p.jobsChan <- job
	return nil
}

// worker is the long-running execution loop binding 1 PDFium instance per goroutine.
func (p *PDFWorkerPool) worker(workerID int) {
	defer p.workerWg.Done()

	// Acquire a dedicated PDFium handle for this worker's lifetime
	instance, err := p.pdfiumPool.GetInstance(time.Second * 10)
	if err != nil {
		log.Printf("[Worker %d] Failed to acquire PDFium instance: %v", workerID, err)
		return
	}
	defer func() {
		_ = instance.Close()
	}()

	log.Printf("[Worker %d] Started and ready for export jobs", workerID)

	for job := range p.jobsChan {
		// Check for cancellation before executing heavy rendering
		if job.Ctx != nil && job.Ctx.Err() != nil {
			job.ResultChan <- ExportResult{
				JobID: job.JobID,
				Err:   ErrJobCancelled,
			}
			continue
		}

		startTime := time.Now()

		// Execute core PDFium flattening engine call
		flattenedBytes, err := FlattenDocument(instance, job.PDFBytes, job.Annotations)
		elapsed := time.Since(startTime)

		res := ExportResult{
			JobID:          job.JobID,
			FlattenedBytes: flattenedBytes,
			Duration:       elapsed,
			Err:            err,
		}

		// Dispatch result back to caller channel
		select {
		case job.ResultChan <- res:
		case <-time.After(2 * time.Second):
			log.Printf("[Worker %d] Timed out delivering result for Job %s", workerID, job.JobID)
		}
	}

	log.Printf("[Worker %d] Shutdown complete", workerID)
}

// Shutdown gracefully drains remaining jobs and destroys PDFium instances.
func (p *PDFWorkerPool) Shutdown(ctx context.Context) error {
	var shutdownErr error

	p.closeOnce.Do(func() {
		p.closedLock.Lock()
		p.isClosed = true
		p.closedLock.Unlock()

		// Close job queue to stop workers from accepting new jobs
		close(p.jobsChan)

		// Wait for active workers to complete with context deadline
		done := make(chan struct{})
		go func() {
			p.workerWg.Wait()
			close(done)
		}()

		select {
		case <-done:
			log.Println("[PDFWorkerPool] All workers drained successfully")
		case <-ctx.Done():
			shutdownErr = fmt.Errorf("shutdown context deadline exceeded: %w", ctx.Err())
			log.Println("[PDFWorkerPool] Forcefully shutting down pool...")
		}

		// Close underlying PDFium library pool
		if err := p.pdfiumPool.Close(); err != nil {
			log.Printf("[PDFWorkerPool] Error closing PDFium pool: %v", err)
		}
	})

	return shutdownErr
}

Go
func main() {
	// Initialize a worker pool matching CPU core capacity (e.g., 8 workers, buffer 100)
	pool, err := NewPDFWorkerPool(8, 100)
	if err != nil {
		log.Fatalf("Failed to create worker pool: %v", err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()

	// Construct result channel for async response
	resultChan := make(chan ExportResult, 1)

	job := ExportJob{
		JobID:        "export_job_99812",
		SubmissionID: "sub_33421",
		PDFBytes:     []byte("%PDF-1.7 ..."), // Raw submission PDF bytes
		Annotations:  []AnnotationItem{},     // Parsed SpeedGrader JSON annotations
		ResultChan:   resultChan,
		Ctx:          ctx,
	}

	// Submit job to pool
	if err := pool.Submit(job); err != nil {
		log.Fatalf("Failed to submit job: %v", err)
	}

	// Wait for result
	select {
	case res := <-resultChan:
		if res.Err != nil {
			log.Fatalf("Export failed for job %s: %v", res.JobID, res.Err)
		}
		fmt.Printf("Successfully generated flattened PDF (%d bytes) in %v\n", 
			len(res.FlattenedBytes), res.Duration)

	case <-ctx.Done():
		log.Fatal("Overall request context timed out waiting for PDF export")
	}

	// Graceful shutdown on application signal
	shutdownCtx, shutdownCancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer shutdownCancel()
	_ = pool.Shutdown(shutdownCtx)
}
Architecture & Concurrency Highlights
	single_threaded.Init() Binding: Uses go-pdfium's single-threaded configuration, which pins PDFium runtime bindings to isolated OS-level worker threads. This avoids CGO memory corruption caused by cross-thread C pointer swapping.
	Goroutine-Bound PDFium Instances: Calls p.pdfiumPool.GetInstance() once per worker lifecycle inside worker(). Reusing PDFium instances avoids C library allocation overhead per document export.
	Graceful Shutdown (Shutdown): Uses a thread-safe sync.Once and RWMutex guard to prevent new job submissions while allowing pending items in the channel buffer to drain safely before releasing PDFium resources.
	Context-Aware Pre-Check: Evaluates job.Ctx.Err() inside the worker loop before running flattening calculations, skipping rendering for clients that disconnected or canceled their HTTP request.

name: LMS CI/CD

on:
  push:
    branches: [ main ]

  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Build Docker image
        run: docker build -t lms-service:${{ github.sha }} .
      - name: Run tests
        run: npm test

  push-image:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: Login to registry
        run: echo $CR_PAT | docker login ghcr.io -u $GITHUB_ACTOR --password-stdin
      - name: Push image
        run: docker push ghcr.io/org/lms-service:${{ github.sha }}

  deploy:
    needs: push-image
    runs-on: ubuntu-latest
    steps:
      - name: Apply Kubernetes manifests
        run: kubectl apply -f k8s/
